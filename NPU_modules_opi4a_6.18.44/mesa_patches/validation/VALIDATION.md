## 3. Rebuild from pristine + patch (cross, proxmox)

The exact original Meson command was used:

```bash
meson setup build \
  -Dbuildtype=release -Dgallium-drivers=etnaviv -Dteflon=true \
  -Dvulkan-drivers= -Dplatforms= -Dglx=disabled -Dgbm=disabled \
  -Degl=disabled -Dgles1=disabled -Dgles2=disabled -Dopengl=false \
  -Dshared-glapi=disabled -Dllvm=disabled \
  --cross-file=/tmp/opencode/cross_no_udev.txt
ninja -C build src/gallium/targets/teflon/libteflon.so
```

Two conditions had to be matched to the original build:

1. The tree must **not** be a git checkout, so `MESA_GIT_SHA1` stays empty
   (`#define MESA_GIT_SHA1 ""`). The original `/root/builds/mesa-26.0.8` is not
   a git repo; a rebuild in a `git init` tree embeds a different version
   string.
2. `libudev` must not be found by the cross pkg-config, because the original
   build did not have `-DHAVE_LIBUDEV`. A wrapper pkg-config that returns
   failure for `libudev` reproduces this without modifying the sysroot.

With those two conditions, the compile and link commands are identical to the
original build (after normalizing the build-directory path), and all generated
headers match except `src/etnaviv/isa/encode.h`.

`encode.h` is generated by Mesa's isaspec Python code. Its local variable /
assignment ordering is nondeterministic under Python hash randomization, so a
fresh generation produces semantically identical but differently ordered C.
That made the first fresh rebuild differ:

| Build | SHA256 |
|---|---|
| First fresh rebuild (`git init`, with libudev) | `f1ed3bbac82613b02b51dba47aa4f7d610f0cab3baa8725e436a19d5f78d8f87` |
| Exact-environment fresh rebuild (no git, no libudev) | `91d18b3608a0c024f62d846fe95a0aa0e90e5bdce14749b992af3b28e49c59de` |
| Exact rebuild after restoring the original generated `encode.h` and relinking | `10bd3eae0d08427fecd47527fed8e796aaed2ae75c6d5fa21ad8c8574b009576` |
| `../lib/libteflon.so` (shipped reference) | `10bd3eae...` (same) |

**Result: byte-for-byte identical to the shipped delegate.** The patch is
therefore a complete and exact source representation of the shipped
`libteflon.so`; the only build-to-build variation is the ordering inside the
generated isaspec header, which does not change behavior.

## 4. Functional smoke test (Orange Pi 4A)

The fresh rebuild is byte-identical to the shipped `../lib/libteflon.so`, so its
hardware behavior is identical by construction. The shipped artifact was
already validated on the T527 VIP9000 (`conv2d.tflite`, sysfs active-time delta,
clean autosuspend). A fresh run can be repeated with:

```bash
cd ..
sudo ./NPU_enable.sh enable
~/venv_npu/bin/python3 smoke_test/test_npu_smoke.py
# optional: swap in a rebuilt library and repeat
sudo ./NPU_enable.sh disable   # restore the desktop GPU state
```

Because the artifact is byte-identical, no additional behavioral difference is
possible. The smoke test was not re-run in this session only because the NPU
module is intentionally blacklisted when idle and enabling it requires root
(`NPU_enable.sh`).

## 5. Native rebuild (optional)

The Orange Pi 4A currently lacks `libdrm-dev`, and has 3.7 GB RAM / ~1.5 GB
free. A native build needs `sudo apt install libdrm-dev` and should use
`ninja -j2`/`-j4` to avoid OOM. The cross-build above is the authoritative
reproduction path; native rebuild is optional.
